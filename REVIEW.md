# Чек-лист для самопроверки и код-ревью

## Конструирование кода

- [ ] Прочитать файлы, где были правки, сверху вниз, задать вопросы и оставить замечания.
- [ ] Проверить, что импорты используют алиасы, а не относительные пути
- [ ] Проверить, что нет дублирования кода
- [ ] Проверить соблюдение правил типизации: строгие пропсы (отсутствие расширений через MUI-типы), `FC` для компонентов.
- [ ] Проверить мемоизацию: `useMemo` для колонок таблицы, схем валидации, тяжёлых вычислений. Зависимости колонок не должны быть связаны со строками таблицы.
- [ ] Проверить обработку ошибок в асинхронном коде: `try/finally` для UI-состояний (loading, disabled).
- [ ] Проверить эскейпинг пользовательских данных в URL (`encodeURIComponent`).
- [ ] Если добавляются/изменяются экшены API — проверить нейминг (`create*`/`edit*`/`delete*`), типизацию ответа, что PATCH отправляет только изменённые поля.

## Формы

- [ ] Вбить неадекватные данные в поля и проверить валидацию.
- [ ] Проверить все другие CRUD-операции в местах правок и в местах рядом.
- [ ] Проверить, что `initialValues` вынесены в константу, затипизированы, и не содержат объект бекенда напрямую.
- [ ] Проверить, что кнопка «Добавить» (создание) / «Сохранить» (редактирование), форма блокируется при сабмите.

## Вёрстка и UI

- [ ] Осмотреть вёрстку на соответствие макетам.
- [ ] Осмотреть названия полей, хелпер-текстов и сообщения валидации на соответствие макетам.
- [ ] Проверить кавычки: `«»` в RU, `""` в EN.
- [ ] Проверить аббревиатуры: через дефис в RU (`IP-адрес`), через пробел в EN (`IP address`).
- [ ] Проверить пустые состояния: прочерк `—` при null/пустой строке, корректная заглушка таблицы.
- [ ] Проверить в светлой и тёмной теме (особенно иконки и цвета).

## Таблицы и колонки

- [ ] Если добавляется новая колонка, проверить фильтры.
- [ ] Проверить сортировку новых колонок.
- [ ] Проверить CRUD-операции.
- [ ] Проверить quick filter (поиск) — работает ли по новым колонкам.

## Переводы

- [ ] Проверить, что используется `t()` из `useTranslation()` (динамический), а не `i18n.t` (статический).
- [ ] Проверить, что `.po` файлы содержат переводы для новых строк (RU обязателен).
- [ ] Если есть новые/изменённые строки — запустить `yarn translate` и проверить, что нет расхождений.

## Финальные проверки

- [ ] Запустить правки, протыкать места правок и места рядом.
- [ ] Проверить и попросить дописать шаги для тестирования.
- [ ] Проверить, что CI проходит (`yarn ci:check` — переводы, неиспользуемые экспорты, типографика, тесты).
- [ ] Проверить время сборки.
